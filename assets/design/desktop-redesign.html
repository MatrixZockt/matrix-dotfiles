Design proposal

Making the desktop readable at a glance

Three proposals, all following the same rule: show the thing, don't name the thing. A wallpaper should be a picture, a file should be its contents, and a system spec should be a shape you recognise before you read a word. Everything below is mockup only — nothing here is wired into the shell yet.

1 · Wallpaper picker — three rows, scrolls down

Built and live now. The grid shows three rows at once and scrolls down when you add more, instead of one long horizontal strip you had to drag sideways. The ＋ tile leads the grid; hovering a tile lifts it and offers a red ×; the wallpaper in use carries an accent ring and a dot.

2 · File manager — show the contents, not the filenames

Today it is a list of names. The proposal is a three-pane manager: places on the left, a live preview grid in the middle, and a details pane on the right that previews the selected file itself — image, PDF, text, video frame, archive listing — instead of telling you its size and moving on.

The preview pane is the whole point: it is contextual, so a PDF shows its first page, a video a frame, an archive its listing, an image its palette — with the one action that file actually wants (“Set as wallpaper”, “Extract”, “Play”).

What this changes

  • Thumbnails everywhere, generated once and cached — the freedesktop pipeline is already there.
  • Instant preview on selection, no open-then-back.
  • Icon size slider (list → 4-up → 6-up) so “overview” is a dial, not a mode.
  • Quick actions tied to the selection: set wallpaper, extract, play, open in editor.
  • Live search with a filter row (Images / Video / Documents / Audio).

How it stays cheap

  • Thumbnails are the existing cache files, so a 4000-file folder reads nothing.
  • Only the selected file is ever decoded for the preview — one image at a time.
  • GridView recycles delegates, so scrolling a big folder allocates nothing new.

3 · Settings — a graphical overview, not a list of values

A settings app should answer “what is this machine and how is it doing” before you go looking. The Overview becomes the identity page: a device card, spec tiles, and the handful of live readings that actually change what you would do next. The heavy real-time graphs stay in the task manager.

The improvement list

Wallpaper

  • ✅ Three-row grid, scrolls down (built)
  • ✅ Add / remove tiles (built)
  • Staggered entrance + hover lift (built)
  • “Apply to both themes” toggle on a tile
  • Drag a file onto the pill to add it

File manager

  • Preview pane for the selected file
  • Thumbnail grid with size slider
  • Breadcrumb + live search + type filters
  • Contextual actions per file type
  • Disk-usage strip per drive in the sidebar

Settings overview

  • Device identity card (host, distro, session)
  • Six spec tiles instead of prose
  • Four flat live bars; graphs stay in the task manager
  • Jump-to-hardware button that opens the merged task manager page
  • Icon rail with the same language as the shell

Shared rules

  • One tile, one idea — never two values in one box
  • Accent = state, never decoration
  • Frosted glass for floating chrome, flat for content
  • Animate transform only — no relayout per frame
  • Recycle delegates in every grid and list
