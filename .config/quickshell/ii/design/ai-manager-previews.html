Two designs for the fourth tab of the middle popup, replacing AI usage (the FlareData subscription grid) with a local LLM manager: start and stop llama.cpp, watch it run, switch models, change sampling. Every figure shown is measured from the real server on this machine — 45.4 tok/s generation, n_ctx 15104 × 4 slots, Qwen3-8B-Q4_K_M. The tab's label and icon change with it: AI usage becomes Local AI.

Design A — Console

Why this shape. The hero row is the whole control surface: the dot is the state, the model name is the identity, the pill is the switch. The four gauges are the same shape the System tab already uses, so the two tabs feel like one card. Restart required: ctx, parallel, offload layers and flash-attention are launch arguments — moving one shows the new value greyed with a "restart to apply" marker, rather than pretending a live reload happened. Temperature and the top-p/top-k sliders do apply live, because POST /props takes them.

B — Manager

The same information, organised as a manager rather than a readout: a left rail of sections, one full pane on the right. Slower to scan, but it has room for the things a flat list runs out of — the server log, the full argument line, per-slot history.

Design B — Manager

Trade-off. B scales to a log tail and a full argument editor, which is where a llama.cpp user actually ends up. But it costs the one-glance read: the throughput numbers are two clicks deep, and the card carries a rail whose other three sections start out empty for most people. A is the same information at a single glance; B is the shape that grows.

Deliberately not an error state. A local model server being off is the normal condition, not a fault — so this reads as a fact with an offer, not a red failure. The remembered model and arguments are still shown, because "start it the way I had it" is the whole reason this tab exists.

Both designs read the same four endpoints and write the same three: read GET /health, GET /props, GET /slots, POST /props · start/stop a managed llama-server process (systemd user unit, so it survives the shell) · models a .gguf scan of ~/Models.
